# 录制中转写与自动断句

2026-10-25，本地实现与验证。AUP 部署本次未变更。

## 行为

- 录制中显示可修正的临时字幕，停止录音之前即可看到识别结果。
- 一段录音识别出多句话时，按中文句号、问号、感叹号及英文句末标点拆成独立原文条目，分别翻译。英文常用缩写、姓名首字母、版本号及小数点不直接作为句界；逗号不作为句界。
- 临时字幕不写入字幕表、不翻译、不生成纪要。最终识别失败不会拿旧预览冒充确认结果。
- 前端保留约 240ms 前置音频、160ms 尾音；降低固定音量阈值并加入滞回和静音噪声估计。少于 160ms 有声的短噪声不会创建孤立预览。约 800ms 停顿确认一段，连续语音最长 12 秒确认。
- 第一次约在收集 800ms 音频后请求预览，之后每 1.2 秒发送累计音频。后端同片段同时只有一个预览推理，积压时只保留最新待识别版本。网络传输和推理速度不足时，更新间隔会变长。
- 若最后预览与最终音频字节完全相同，复用识别结果。过时预览不会覆盖最终原文，不重复入库。不同音频按接收顺序确认。
- 音频处理回执在确认原文后立即发送，不等待翻译完成。暂停与结束共享同一个收尾 Promise，避免快速连续操作漏掉尾段。
- 断线或直接结束时，服务器会保存并确认最后收到的累计音频；浏览器尚未发送的最后部分仍可能丢失。

开始采集前先准备模型：本机加载并预热翻译、纪要模型，然后预热 ASR。后续每次开始录音会再次轻量预热 ASR，减少模型切换或内存换页造成的首次延迟。该阶段界面显示“准备录音”，正式采集开始后才显示“录音中”。翻译或纪要预热失败会明确提示，ASR 仍可继续使用；ASR 准备失败则不开始采集。不对兼容 API 后端发送额外的合成预热请求。

## 时间与来源

同一来源音频拆出的句子共享这段音频的实际起止时间和回放文件，没有伪造逐句时间戳。播放按钮标识为来源录音，SRT 将同一来源片段内的句子合并为一个时间段，避免产生多条重叠字幕。

这是累计窗口重复解码实现的滚动识别，尚未接入模型原生流式缓存解码。断句依赖最终识别中的标点；若模型漏标点，仍可能保留较长句子。长时间无停顿触发 12 秒上限时仍可能在一句话中间切开，当前没有跨窗口重叠纠错。

## 本地验证

设备为 Ryzen 5 7640HS，CPU，6 线程，torch 2.14.1+cpu，ASR 为 Qwen3-ASR-0.6B-hf / bfloat16。翻译仍为 Hy-MT2-1.8B Q4_K_M / llama.cpp，纪要为 Qwen3-0.6B 抽取式。固定音频来自 Qwen 官方 `asr_zh.wav`，4.204 秒。

预热后直接通过 WebSocket 逐步增加音频长度的单次检查：

| 输入音频长度 | 临时识别文本 | 请求到返回 |
|---|---|---|
| 1.0 秒 | 甚至。 | 0.617 秒 |
| 2.4 秒 | 甚至出现交易几乎。 | 1.001 秒 |
| 4.204 秒 | 甚至出现交易几乎停滞的情况。 | 1.344 秒 |

最终提交同一份完整音频，复用最后预览，收到确认回执耗时 0.046 秒。此表仅为单样本请求耗时，不能代替用户端字幕延迟，也不是识别准确率评测。临时标点和文字会被后续上下文修正。

真实浏览器测试通过 AudioContext 将上述公开 WAV 注入麦克风接口，再由 AudioWorklet、VAD、WebSocket 和真实 Qwen 处理；本机首次准备全部模型约 49.3 秒，正式采集后约 2.05 秒看到第一条临时字幕，录制尚未停止时已收到确认原文。同步暂停与结束、翻译、纪要及保存通过。此为单次自动化音频回放检查，不代表物理麦克风在不同音量和噪声下的表现。

产物保存在不入 Git 的 `artifacts/live-asr-warm.json`、`artifacts/live-browser-real.json`、`artifacts/desktop-live-real.png`。固定输入与进程状态不同会影响耗时，本地 CPU 仍可能发生排队，不能据此保证 AUP 的 GPU 延迟。

## 文件导入切分补充

此前更新只修改了录音流程，文件导入仍按每 10 秒取一块 PCM，随后才按识别标点分条。这会把长句的音频上下文截断；后续文字拆句不能修复音频硬切造成的缺字。

现已移除固定 10 秒切片。文件导入会先扫描全文件的 20ms 音量帧，按自适应阈值检测约 350ms 的停顿，保留约 240ms 前置音频和 160ms 尾音。很短的尾音或爆音优先与相邻上下文合并，不单独生成识别条目。实时录音仍采用约 800ms 停顿和 12 秒上限，二者不再混淆。

一段连续语音超过 30 秒时，在上限前 5 秒内优先找至少 80ms 的短静音；没有合适停顿时找低能量位置，最后才按时长兜底。界面会提示实际语音片段数以及兜底段数，避免把兜底切分说成自然句界。30 秒是应用的资源与延迟取舍，不是模型只能处理 30 秒。

ASR 对超过 15 秒的文件片段使用随时长增长的输出预算，避免继续套用实时短片段的 token 上限。若仍达到输出上限且没有结束标记，会明确报错，不把被截断的文字保存成完整结果。来源音频仍保留。

完整标准化文件、派生片段和样本范围清单会保存在会议的 `audio/.../imports/` 目录中。停顿切分保持实际音频偏移；省略的长静音仍在完整文件中，没有伪造逐词时间戳。识别后仍按标点拆句，当前依据是声音停顿与模型标点，不能保证嘈杂背景下或完全无停顿讲话时的语义句界。

新增检查覆盖：11 秒无停顿不切开、100ms 犹豫停顿不拆句、不同时间位置的自然停顿、30 秒上限前选择短静音、65 秒连续输入的样本完整性、低音量、尾部短声、完整来源持久化及静音文件拒绝。

本次完整 Python 回归为 60 项通过，浏览器回归通过。真实 Qwen 检查中，约 10.108 秒的公开样本组合在自然停顿处产生两个输入片段，范围约为 0–4.36 秒、4.70–9.26 秒；压缩停顿后的 18.52 秒连续测试音频作为一个片段完整识别，没有在第 10 秒被截断。结果见本地 `artifacts/upload-segmentation-real.json`。这些组合／重复样本用于检查切分与长输入兼容性，不作为自然语义分句或识别准确率评测。
